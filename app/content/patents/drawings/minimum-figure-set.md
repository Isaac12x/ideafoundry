There is no fixed number. The rule is functional: drawings must show every feature in the claims (37 CFR 1.83(a)), and anything needed to understand the invention must be in the application on the filing date, because a necessary drawing cannot be added later (new matter).

Practical minimum: one figure per independent claim element group, so each claim feature appears somewhere.

For a software invention, a typical set:
1. System or architecture block diagram (devices, servers, modules).
2. Flowchart of the main method, one box per claimed step.
3. Data structure or sequence diagram, if the claims recite data or message flow.
4. User interface view, if a screen element is claimed or distinguishes the invention.
5. Hardware block diagram, if a processor/memory claim exists, so "processor" and "memory" have a drawing home.
6. One or more variant figures for important alternative embodiments.

Mechanical: assembled view, exploded view, key cross-sections, and a view of each claimed moving part.

Method: list claim elements, then map each to a figure and numeral. A feature with no figure is a gap; add a figure or drop the feature.

Every figure needs a one-line entry in the Brief Description of the Drawings, and every numeral must be discussed in the Detailed Description.

Provisionals may use rough figures, but the same coverage logic applies, since that is the support you will rely on for the priority date.

Example: claim 1 recites "decoding a QR code and comparing a URL to a list". FIG. 1 shows the system, FIG. 2 the flowchart with those two steps as labeled boxes.
