An embodiment is one concrete way of implementing the invention. Describing several embodiments gives broader support for the claims and helps fallback positions.

Good practice:
- Use "in some embodiments" or "in one embodiment" to introduce variants, so the description is not read as limiting the invention to the example.
- Describe alternatives for each key element (local or remote database, software or hardware).
- Include a statement that the disclosure is exemplary and the claims define the scope, but note boilerplate alone does not cure missing support.
- Use consistent terms between description and claims; define any special term.
- Avoid saying "the invention is" or "the present invention requires" for features that are optional, as courts may use such statements to narrow claims.

Example: "In some embodiments, the reputation database is stored locally; in other embodiments it is hosted on a server and queried over a network."

Tip: describe the same function in method and system language so each claim category finds support.
